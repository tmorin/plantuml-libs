# Wave 003 — Workdir Generation Hardening — Business Case

## Context

Wave 002 (closed 2026-10-12) made a bad archive fetch fail loudly, restored
AWS's two example templates and re-synced `distribution/` for AWS,
Font Awesome and Simple Icons. Its progress log recorded, under "Left open",
what it found and chose not to fix. This wave is sourced from that list:
**this repository has no `docs/bkg/` or `docs/ana/` register**, so there is
no backlog item or analysis to cite, and `sources` is empty by design.

Re-verified against the repository on 2026-11-07, each item still stands:

- `npm run generate:workdir` does not check that a package's declared
  example templates exist, nor that an item's `icon_reference` URN resolves
  to an icon of the generated library. The two AWS defects wave 002 hit
  (templates deleted by the folder rename, a stale `groups.csv` reference to
  `AppIntegration`) were only caught by a full CI render, the one check the
  repository's rules keep off the developer's machine.
- `source/generator/workdir/archive.ts` caches a 200 response whatever its
  body is, and `extractArchive` skips extraction as soon as the destination
  directory exists, so an interrupted extraction is trusted on the next run.
- Measured today with `generate:workdir -p aws`: 27 families are produced and
  9 have no row in `source/library/packages/aws/families.csv`
  (`ArtificialIntelligence`, `CloudFinancialManagement`, `Databases`,
  `Games`, `GroupIcons`, `IoT`, `ManagementTools`, `MigrationModernization`,
  `SecurityIdentity`). Those families get default styling.
- `scripts/resolve-aws-icons.mjs` still builds a `newVersion` quarter label
  (`aws-q<n>-<year>`) from the abandoned versioned-folder scheme, and a live
  run was reported to resolve `Icon-package_01302026` while the repository is
  pinned to `07312026`. The upgrade how-to now says only `downloadUrl` and
  its embedded date matter.

Baseline measured the same day: `npm run lint` clean, `npm test` 11 passing,
`npm run generate:workdir -- -w <scratch>` (all packages) exits 0 in about
two minutes, TypeScript only, no Podman.

## Problems / Opportunities

- A broken reference fails late and expensively: after a long CI render
  instead of in the two-minute, container-free workdir step. Moving the
  check there turns the next AWS-style rename into a fast, local failure.
- A truncated download or extraction is silent corruption for any package's
  next upgrade, the same class of defect wave 002 closed for HTTP errors.
- The upgrade tooling for AWS still speaks a scheme that no longer exists,
  which is a recurring source of confusion for whoever upgrades AWS next.
- Nine AWS families are visibly unstyled in the generated bootstrap.

## Options & Recommendation

**Option A (recommended):** one phase, three independent runs, one per
concern: a reference check in the workdir generator, archive integrity, and
AWS content/tooling (family colours, resolver script). The runs touch
disjoint files and none needs another's result.

**Option B:** one run per item of the list (four to five runs). Rejected:
the AWS family rows and the resolver script share one package and one
how-to and have no separately distinguishable exit evidence, so splitting
them costs a run's fixed overhead for nothing.

**Option C:** one single run for everything. Rejected: it mixes a
cross-package generator change with AWS-only content, so a failure in one
blocks evidence for the others.

**Option D (adopted, as a second phase):** end with a `distribution/aws`
regeneration through the `package-builder.yaml` GitHub Action, so the new
family colours reach the committed bootstrap and the next tag does not ship
a stale one. It is a separate phase after the generator and AWS changes,
because it needs them pushed first. A local Podman regeneration is rejected
as before: it takes hours of CPU, and the Action runs on its own runner.

## Vision

`generate:workdir` is the fast gate: a package that declares an example
whose template is missing, or an icon reference that resolves to nothing,
fails there with a message naming the package and the reference. A cached
archive is only ever a complete, valid zip that was fully extracted. Every
family the AWS package produces has a colour, the AWS resolver script
reports the same identifiers (`FOLDER_DATE`, download URL) the how-to tells
the maintainer to copy, and `distribution/aws` was regenerated by the
`package-builder.yaml` GitHub Action with those colours, never by a local
render. The Google redesigned-icon-set question and the release stay with
the human.
